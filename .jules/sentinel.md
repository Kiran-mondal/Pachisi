## 2024-08-24 - SSRF in Serverless Function\n**Vulnerability:** The API endpoint `api/penpot.js` blindly trusted the user-provided `req.query.fileId` parameter and passed it directly to the Penpot API using a sensitive backend authentication token (`PENPOT_ACCESS_TOKEN`). This allowed an attacker to fetch any file the token had access to, leading to Server-Side Request Forgery (SSRF) and potential leakage of sensitive design files.\n**Learning:** Serverless functions that proxy requests to third-party APIs using backend credentials must never trust user input for determining the target resource. \n**Prevention:** Avoid passing user-controlled parameters directly into backend-authenticated API calls. Use environment variables (e.g., `PENPOT_FILE_ID`), hardcoded values, or an explicit allowlist to strictly control which resources can be accessed.
